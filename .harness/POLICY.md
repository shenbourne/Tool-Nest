# Harness improvement policy

Review the agent harness after a repeated, evidence-backed workflow failure. Examine context routing, instructions, skills, scripts, hooks, and CI. Prefer the smallest durable fix: documentation for missing knowledge, a workflow module for repeatable judgment, or a script/CI check for a deterministic gate.

Record the finding, evidence, proposed change, owner, and follow-up result in `FINDINGS.md`. Implement a harness change as a distinct reviewed task after user approval for that proposal. Keep application requirements and scope in the project layer.
