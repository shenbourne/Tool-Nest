# 工具交互逻辑审计

Status: in-progress

## 问题陈述

`apps/web/src/tools/` 下有 209 个工具组件。它们由不同来源项目迁移而来（1Panel-Tools、it-tools、omni-tools、MyIP），迁移过程中保留了各自的交互习惯，导致：

- 部分控件的点击/输入不产生任何可见效果（死控件）
- 部分异步操作失败后静默无反馈，用户无法区分「无结果」与「出错」
- 部分工具在边界输入下静默丢弃数据或产出错误结果
- 工具之间的基础交互（复制、重置、错误提示、空状态）不一致

本审计逐项检测全部 209 个工具的交互逻辑，产出可复现、带证据的问题清单，作为后续统一修复的依据。

## 范围

- 纳入：`apps/web/src/tools/<tool>/` 下的 Vue 组件及其同目录 service/types/`index.ts` 中的交互相关逻辑。
- 纳入：工具组件通过 `ToolLayout`、`@toolnest/shared`、composables 共享的基础交互行为。
- 不纳入：`apps/server/`、纯样式/视觉问题、i18n 文案翻译质量（另有批次处理）、架构与安全设计（除非直接造成交互缺陷）。

## 判定标准

本次审计接受两类问题：

1. **功能性缺陷**：确定的交互逻辑 bug。点击无效、状态不同步、边界越界、异常未处理、数据丢失等。
2. **体验一致性问题**：缺失反馈 / loading / 校验 / 空状态 / 错误态，文案与行为不符，同类工具交互不一致。

### 缺陷分类（D1–D12）

| 编号 | 分类 | 说明 | 反例（本仓库真实样例） |
| --- | --- | --- | --- |
| D1 | 死控件 / 无效交互 | 控件存在但点击/输入不改变任何状态，或控件禁用逻辑错误导致永远不可用 | 无 |
| D2 | 状态不同步 / 陈旧状态 | 输入变化后输出未重算；模式/选项切换后未清理依赖状态；重置不完整 | 无 |
| D3 | 数据丢失 / 破坏性操作 | 静默丢弃输入内容；覆盖用户编辑；破坏性操作无确认 | `list-sort` 静默删除空行 |
| D4 | 异常未处理 / 静默失败 | async/解析无 try/catch，或 catch 后不告知用户；浮动 promise 无处理 | `dns-resolver` `catch {}` 后结果为空且无提示 |
| D5 | 反馈缺失 | 复制/下载/保存/执行无成功或失败提示；长任务无 loading | `hash-text` 复制无反馈 |
| D6 | 边界 / 逻辑错误 | off-by-one、大小写、正负号、除零、空输入、字符串比较误用 | `list-sort` 未用 numeric 排序（item10 < item9） |
| D7 | 长任务交互 | 无进度 / 无取消；执行期间控件未禁用导致并发重复执行 | 无 |
| D8 | 输入校验缺失 | 非法输入被静默接受并产出错误结果；无上下界约束 | 无 |
| D9 | 键盘 / 无障碍交互 | 无回车提交；结果区无 aria-live；disabled/readonly 语义误用 | 无 |
| D10 | 模式 / 选项一致性 | 选项变更未刷新依赖结果；默认值与文案不符；切换丢失内容 | 无 |
| D11 | 资源生命周期 | `setInterval`/worker/`URL.createObjectURL`/事件监听/媒体流未在卸载时释放 | `chronometer` 间隔未置空（低危） |
| D12 | 结果呈现错误 | 错误信息被写入结果区、结果被标注为错误的类型/单位 | `text-replacer` 非法正则时把错误文案当输出 |

### 严重度

- **P0 — 阻断**：结果错误或数据丢失，用户据此决策会被误导。如 D3、D6、D12。
- **P1 — 严重**：功能不可用或失败不可见。如 D1、D2、D4、D7。
- **P2 — 一般**：可用但有明显缺失。如 D5、D8、D10。
- **P3 — 轻微**：一致性/体验细节。如 D9、D11（无实际泄漏风险时）。

### 证据要求

每条发现必须包含：

- `文件:行号`（可为范围）
- 触发条件（什么输入/什么操作）
- 观察到的错误行为（期望 vs 实际）
- 分类编号与严重度
- 判定为「真实缺陷」而非「设计选择」的简短理由

无法给出触发条件的猜测不得列入清单。

## 产物

- 本文件：范围、标准、分级。
- `findings.md`：逐工具问题清单，按工具分组，含分类、严重度、证据、修复建议。
- `issues/<NN>-<slug>.md`：确认修复阶段，每个原子修复任务一张工单。

## 执行方式

1. 分 11 批将 209 个工具分派给并行子代理，每批完整阅读组件与配套文件。
2. 汇总去重，抽样复核误报。
3. 输出 `findings.md` 供确认。
4. 确认后逐项修复，遵循 AGENTS.md：一任务一提交，修复后跑 lint / type-check / test。
